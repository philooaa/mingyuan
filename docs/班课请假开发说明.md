# 班课请假

## 1. 范围与复用

家长首页“请假申请”、教师首页“请假审核”接入真实班课请假业务。仅处理班课，不接入一对一、补课、课包或费用。

现有数据库没有请假申请表，`edu_class_sign_in.sign_status=3` 只表示签到结果，不能承载申请、撤回、审核及历史。因此新增 `edu_class_leave_request`，通过现有报名、学生、课次账户和排课外键关联，使用 RESTRICT 保留引用历史，不修改 `sys` 表。

复用 `ScheduleCalendar`、`ScheduleAvailabilityService` 的真实排课与调课日期。没有配置可靠日期或上课时分的课程不提供可选课次；不猜测日期。

## 2. 流程与权限

1. 家长选择本人孩子、有效的已报名班课及具体课次，填写最多255字的原因。开课开始时刻及之后不能提交。
2. 当前授课教师同意或拒绝，拒绝须填写原因。家长只能撤回待审核申请；审核通过后页面提示联系授课老师处理。
3. 撤回或拒绝后，可在开课前重新申请。复用同一孩子同一课次的申请记录，并追加历史，不删除或覆盖原申请及审核过程。
4. 申请状态为 `PENDING/APPROVED/REJECTED/WITHDRAWN`。申请重提和审核更新版本号，过期页面不能处理重提后的申请。重复提交同一申请不会重复增加历史。
5. 后端按登录身份校验家长、孩子报名和当前授课教师；客户端传入的家长或教师编号不能决定权限。列表、详情、历史和待审核计数均限制归属。
6. 使用孩子稳定编号，旧记录只在可靠关联时沿用孩子编号；未关联旧记录以报名编号区分，禁止按姓名推定同一个孩子。

教师首页请假审核图标及审核页待审核栏显示红色数字角标。仅统计本人班课待审核申请，0隐藏、超过99显示99+。首页显示期间每30秒刷新，进入页面或返回首页刷新；身份变化后丢弃旧响应。

## 3. 与考勤衔接

- 审批不直接写入或更改已有考勤。教师打开点名页时，通过报名编号带入已同意申请的“请假”状态；其他学员、试听和调课学员保持原逻辑，老师仍可按实际情况选择签到结果。
- 任一管理员已经确认的课次不再预填覆盖，也禁止覆盖式签到提交；管理员原复核及图片更新入口保留。
- 点名、复核、申请、撤回与审批共用排课行锁，避免并发覆盖考勤或同时审核、撤回。
- 原签到唯一索引按姓名区分，会阻断同名学员。兼容迁移将报名学员改为按报名编号唯一，无报名编号的自由学员仍按姓名唯一；不更新或清除原考勤数据。

## 4. 增量 SQL

停止后端并完整备份，确认学生身份及课次账户基础结构已安装，按顺序执行：

1. `database/migrations/20261011_class_sign_identity.sql`
2. `database/migrations/20261011_class_leave.sql`

两份迁移已在隔离副本重复执行。签到迁移遇到重复身份或非预期索引／生成列会停止，必须人工核对，不能自动合并考勤。MySQL DDL不支持整组事务回滚，执行中断应保留备份、核对已生效的结构后继续。不要执行破坏性历史 SQL；不要将整库备份或凭据提交 Git。
