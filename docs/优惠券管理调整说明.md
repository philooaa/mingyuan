# 优惠券管理调整说明

## 页面与范围

小程序管理员首页使用“优惠券管理”入口；若依仍使用已有优惠券管理菜单。两端统一包含券模板、发放优惠券、发放记录和推荐奖励。推荐奖励继续提供绑定、达标推荐、发券和异常处理；待奖励审核与异常显示角标。原推荐路由保留兼容，隐藏重复菜单入口。

券仍为现有课程固定金额抵扣券：无门槛抵扣或满减券。不新增折扣券、课次券或商城券。家长优惠券属于家长账号，在孩子间共用；实际是否可用由课程、学科、金额门槛和有效时间共同决定。

## 模板和查询

- 学科使用现有 `edu_subject` 字典及排课保存的学科名称，可单选、多选、全选；全选为不限学科。
- 模板选择现有课程，显示课程名、授课教师、学科和校区。课程限制和学科限制必须同时满足。
- 家长按账号手机号查询，支持3至11位数字前缀；完整11位精确匹配。显示家长姓名及手机号，内部仍按稳定用户ID关联与防重。
- 普通发券预览模板规则及接收名单、人数、发券数；同一模板每位家长仅一张。推荐奖励按推荐记录计算，同人跨推荐的合法奖励保留。
- 已发模板不能修改名称、金额、门槛、课程、学科或有效期。允许启停，后端保留提高发行上限能力。

| `CouponService.available/discount` | 可用券列表及实际付款统一校验真实排课学科；不信任客户端传入学科。 |

原URL、权限、原参数及返回已有字段保持兼容。未变更原核销、收款、退款、撤回业务状态规则。

## 2026-10-15 小程序事务入口拆分

用户反馈原两层标签页混杂、点击推荐发券后找不到操作位置。小程序优惠券管理现改为目录：发放优惠券、券模板、发放记录、推荐审核、绑定记录、异常处理；每项进入独立事务页，角标分别放在推荐审核和异常处理入口。若依网页入口和后端业务规则继续沿用。

推荐审核勾选后进入独立“发放推荐奖励”页面，明确分为选模板、选接收人、填原因并预览。无已启用模板时显示创建入口，返回时保留原推荐记录、接收角色及原因；身份变化后禁止恢复旧管理员草稿。提交结果未知时保留原批次重试，成功后返回审核页刷新。

复用原coupon-management及referral工具的模板编辑、普通发券、奖励预览和提交，不新增表单业务服务、接口或数据库变更。模板及普通发券弹层补齐明确的四边定位；手机号筛选单独占一行，避免挤压。

新页面：pages/admin-coupon-section、pages/admin-referral-grant。原管理员入口pages/admin-referral保留路径兼容。共享路由组织utils/coupon-navigation.js。原生58模板/WXS及64样式资源编译通过；已覆盖独立跳转、空模板、返回保留草稿、幂等重试和账号切换隔离。本轮未提交Git。

### 手机号自动查询

发券选择家长时，输入至少3位手机号后自动查询，连续输入合并请求；保留查询按钮可立即执行。显示查询中、未找到匹配和失败提示；清空输入恢复默认家长列表。离开页面或关闭选择窗取消等待查询，旧响应不覆盖当前输入。两个测试手机号11111111111、22222222222已在实际发券候选接口核验，各返回对应家长一条。

### 推荐审核返回状态与发券确认修复（2026-10-15）

推荐记录勾选由页面数据统一控制，返回未发放页面或切换分页时保留同一账号、同一筛选的选择；勾选框、底部数量和发券按钮保持一致。改变筛选或切换账号清空选择，跨页多选最多100条。

小程序推荐奖励去掉单独“预览名单”按钮。点击“发券”自动调用原预览接口核验，再以一张确认面板展示模板规则、完整接收名单、人数、券数及原因；确认后才调用原发券接口。取消或离开确认面板未发券且不标记结果未知；预检失败不使用旧预览；已发送但结果未知仍保留原批次重试。原权限、库存、防重及财务业务不变。

补充回归覆盖未发放返回、跨页勾选、筛选重置、账号隔离、自动预检、确认前不提交、取消离开和未知重试。未修改数据库，未提交Git。
