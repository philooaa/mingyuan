# 自定义排课规则：生产数据库兼容与发布

## 变更范围

排课规则模板由 `edu_schedule_rule` 和 `edu_schedule_rule_date` 保存。`edu_course_schedule` 增加四个允许 NULL、默认 NULL 的字段：`schedule_rule_id BIGINT`、`schedule_rule_name VARCHAR(100)`、`schedule_rule_version BIGINT`、`custom_dates TEXT`。已有课程保持原模式和全部原值，不批量填充新字段，不重算课次、价格、报名或账务。

选择规则后，课程持有自己的日期快照；之后修改或停用模板不改变已有课程。新后端统一在网页、小程序、考勤、调课、教室冲突和薪资计算中读取快照。带考勤或锁定课次的课程不能直接替换快照。

生产默认禁止应用自定义规则：`CUSTOM_SCHEDULE_RULES_ENABLED=false`。本地 `local` 配置开启该功能。关闭此开关只阻止新应用/重新应用规则，已经存在的快照仍可读取和处理。普通递推课程继续沿用原逻辑。

## 发布顺序

1. 确认实际线上库名与连接目标，备份数据库并确认可恢复；在隔离的数据库副本演练。至少备份课程表、菜单、角色菜单关联。备份包含业务数据，保留在受控位置，不提交 Git。记录迁移前课程行数、业务字段和账务基线。
2. **先迁移，再部署代码**。针对实际库执行 `database/migrations/20261123_schedule_rules.sql`。它只增表、增可空列、增加菜单与管理员/业务管理员/教务授权，可重复执行；不会删除或覆盖原记录。MySQL DDL 自动提交，不能用普通事务回滚整个文件。脚本将当前会话的元数据锁等待限制为 15 秒；失败时先排查长事务和繁忙写入，确认状态后重跑。不要使用忽略错误继续执行的选项。数据量较大时应在维护窗口评估 ALTER TABLE 的耗时和锁影响。
3. 执行只读检查 `database/checks/20261123_schedule_rules.sql`。两个 missing 结果集都必须为空，四个新字段都应为可空且默认 NULL；检查菜单与角色关联。再与备份基线核对原课程及账务值，而不是只核对行数。已有同名但类型不符的字段/表需人工处理，本迁移不会擅自修改它们。
4. 部署新后端，保持 `CUSTOM_SCHEDULE_RULES_ENABLED=false`；生产继续使用原来的生产配置，禁止启用 `local`、模拟登录或模拟支付。部署新管理网页及兼容 `CUSTOM_DATES` 的小程序。滚动部署期间不要开启新规则写入，否则旧节点可能错误计算自定义日期。
5. 验证现有课程列表、课表、报名、学费、考勤、调课和薪资查询，确认旧模式未变化。确认全部后端节点和管理网页已升级；为小程序采用强制更新/最低版本策略或等待旧客户端退场。**开关本身不检测客户端版本，不能把打开开关当作旧客户端已兼容的证明**。
6. 完成兼容客户端的发布和验证后，显式设置 `CUSTOM_SCHEDULE_RULES_ENABLED=true` 并重启/滚动更新所有新后端节点，再开放自定义规则使用。先在隔离库验证新建规则、应用规则、修改模板后课程快照不变，以及调课/考勤/价格计算。

例如在已确认目标库的 MySQL 会话中，使用 `SOURCE` 执行仓库中的迁移与检查文件。不要把本机测试库名或密码复制到生产命令中。

`20261118_attendance_lesson_guests.sql` 已属于本次开发前的 main 历史，是较早的考勤功能迁移。若线上尚缺 `edu_attendance_lesson_guest`，需单独核对并补执行该已有迁移，不能把它误认为此次新增排课规则的数据变更。

## 回退

- 若还没有创建 `CUSTOM_DATES` 课程：关闭新规则写入，可回退应用版本，保留新增表列和数据即可；无需删列或重导全库。旧代码不使用这些新增结构。
- 若已经存在 `CUSTOM_DATES` 课程：先关闭写入开关，但继续使用能够读取快照的新后端。**不能直接退回完全不认识该模式的旧后端或小程序**。采用向前修复或经过验证的兼容补丁；不能用恢复整库的方式抹去期间新增的报名、支付和考勤。
- 模板日期和课程快照都是业务数据。不要删表、删列、将自定义模式批量改回递推模式，也不要重放会覆盖课程或账务的初始化 SQL。

## 自动化验证

小程序测试涵盖自定义日期展开、取消、跨起止范围调课和旧客户端修改保护。后端 `ScheduleCrudTest`、`ScheduleDateRuleTest`、`ScheduleRuleMysqlTest` 覆盖快照、冲突校验、写入开关、模板编辑、重复迁移和原记录保留。MySQL 集成测试仅在随机创建的 `codex_schedule_rule_test_*` 临时数据库执行，完成后清理。运行时的 MySQL 账号需具备创建/删除测试库的权限，禁止将测试库名改成业务库。
