# 业务管理员

## 权限边界

- 原始超级管理员仍按系统内置 userId=1 识别，不按用户名或前端角色别名识别。
- 新角色 `business_admin` 可登录管理网页，可兼任教务、教师、家长。
- 业务管理员沿用业务接口的管理员校验和全部业务数据范围，并可管理普通用户，但不获得 `*:*:*`，不获得角色、菜单维护权限。
- 仅原始 admin 可以创建、授权、修改、停用、重置密码或删除业务管理员账号。系统角色和菜单的写入操作也仅限原始 admin。
- 普通账号不能通过用户编辑、分配角色、角色用户批量授权等入口变成业务管理员。单纯更名为 admin 不会获得超级管理员身份。
- 开发环境免密码教师选择器不允许业务管理员进入。已有会话的撤销、网页与小程序 Token 的全面隔离不属于此次修改。

## 部署

先备份后端安装包及四张授权相关表，再使用配套后端和 `database/migrations/20261026_business_admin.sql`。

迁移创建角色、分配当前启用菜单并排除账号/角色/菜单管理子树，不自动给任何用户授权，不包含个人账号或密码。以后新增业务菜单，可由原始 admin 授权，或审查后重新运行此迁移补充菜单。

2026-10-26 用户确认扩展为“全部业务权限＋普通用户管理，保留管理员安全限制”。基础迁移后，再执行 `database/migrations/20261026_business_admin_user_management.sql`，仅补充普通用户管理菜单，不修改账号角色绑定；两份迁移均可重复执行。配套后端保留管理员账号保护，并修复优惠券、推荐奖励、课程财务校验遗漏 `business_admin` 的问题。

原始 admin 在“系统管理 → 用户管理”中创建用户并选择“业务管理员”角色。交付前设置独立密码。若手机号或用户名已存在，应先核对是否复用旧身份，禁止直接覆盖或另建重复手机号账号。
