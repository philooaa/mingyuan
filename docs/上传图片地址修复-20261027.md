# 上传图片地址修复（2026-10-27）

## 根因

上传接口同时返回 `fileName=/profile/...` 和根据代理请求生成的绝对 `url`。资料图片上传优先保存了后者，服务器已有地址为 `http://test-admin.mingyuantostars.online/profile/...`：缺少 HTTPS 和 `/prod-api`，请求实际返回管理网页 HTML。文件本身存在；正确 `/prod-api/profile/...` 返回图片。

## 修复范围

- 统一 `public-file-url.js`：相对路径接到当前 API 地址；仅对当前 API 域名的公开 `/profile/` 图片兼容旧地址，补齐 HTTPS/API 前缀，避免重复 `/prod-api`；不改第三方图片地址及本地临时文件。
- 资料上传优先采用后端稳定的 `fileName`，经统一入口生成可访问地址后预览及保存。
- 资料封面、轮播、详情、订单图片，以及作业附件和出勤图片共用地址处理；未改变附件权限或业务数据所属关系。
- 财务凭证、私有资料 PDF、收据仍使用原私有存储及鉴权下载接口，未增加公开访问路径。
- 三类存储目录已复查仍为目录，未再改动目录权限。

## 服务器兼容修复

只更新资料封面 `edu_material.cover_url` 和图片 `edu_material_image.image_url` 中当前测试域名的错误公开图片链接，共 4 条。事务执行，更新前核对对应磁盘文件存在、HTTPS 返回 200 且类型为 `image/*`。未修改商品价格、订单、收款或私有文件。

原链接及新链接备份在服务器私有目录 `/www/backup/mingyuan-material-image-urls-20261027/before-and-after.json`，可按主键恢复。
