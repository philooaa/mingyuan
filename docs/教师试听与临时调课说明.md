# 教师试听与临时调课

仅本地开发。部署前执行 `database/migrations/20261118_attendance_lesson_guests.sql`，保留现有学生、报名和收费记录。

教师点名页的“试听学员”先按姓名查已有学生，未找到时可新建只有姓名的待绑定档案；通过既有待绑定学员页绑定已注册家长。已有同名档案需人工核对。加入记录只对应一个稳定 lesson_id，刷新后保留，不会创建登录账户、报名订单或收费记录。

“临时调课”选择已有学生及其未提交的原课程讲次，调入当前讲次。原讲次从有效应到名单排除该生，并展示已调出的目标课程；目标讲次以调课来源计入名单，原课程其他讲次不变。数据库唯一约束防止同一学生同一原讲次调入多个班级。当前教师仅能维护自己任课的目标课次，原讲次必须存在该学生的正常报名或补录名单。

添加立即保存为课次名单，正式到课和课酬仍须点名提交、教务初审和管理员终审。临时调课的原课程及讲次由后端写入签到备注，审核人员可见。提交后名单快照锁定；原讲次或目标讲次已提交时，教师不能直接添加或取消临时调课，需联系教务核对处理。提交前移除临时调课会恢复原讲次名单。全班调整日期仍走原有排课调课流程。

新增接口：`/miniapp/teacher/attendance/guests`（POST）、`/guests/{guestId}`（DELETE）、`/guests/students`、`/guests/sources`、`/guests/outgoing`（GET）。所有接口由服务端核验有效账号和任课归属；DELETE 使用 scheduleId、classDate 查询参数。教师搜索只返回学员姓名、已有课程和待绑定标记，不返回手机号。

验证：`WeChatMiniApp/tests/attendance-guests.test.cjs`，以及使用独立临时 MySQL 库的 `AttendanceLessonRosterMysqlTest`。测试库不会写入本地业务库或服务器。
