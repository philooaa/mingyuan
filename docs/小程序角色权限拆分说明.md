# 小程序按已有角色拆分

网页端继续创建角色、分配账号及菜单权限；小程序按已有角色切分，不新增角色。手机号登录不新增表；2026-10-19的出勤异常处理需执行本文所列增量数据库迁移。

## 已确认的使用规则

| 已有角色 | 小程序工作台 |
| --- | --- |
| parent 家长 | 本人孩子、报名、约课、考勤、作业、商城订单及本人财务记录 |
| teacher 教师 | 本人授课课程、学员、考勤、请假、作业和教学资料 |
| education 教务 | 课次出勤审核，以及已授权的教室、学员查询和收费财务；可核价、登记及确认收款，不出现发券入口 |
| admin 管理员 | 已授权的业务管理、课次、商城、收费财务和优惠券管理 |

教务和管理员不按校区限制；接口数据范围沿用后端现有实现。教师学员页继续使用 /miniapp/teacher/course 接口，不改为管理员全量学生接口。

## 登录与身份

- 默认统一手机号＋验证码登录，不选择注册角色。验证码有效期5分钟，60秒后可重发；同一验证码只可使用一次，连续错误5次失效，并限制来源IP请求频率。
- 新手机号复用 sys_user 和现有 parent 角色创建家长账号，不创建教师、教务、管理员或新角色。已有手机号保留网页分配的所有有效角色，不因登录自动追加家长角色。
- 一个手机号对应一个账号，一个账号可兼任多个角色。旧库同手机号存在多个未删除账号时明确拒绝登录，管理员核对后处理；不按第一条匹配，不自动合并孩子或财务记录。停用账号不能通过重新注册绕过。
- 首页只显示 getInfo 返回的已授权角色，单角色直接进入。没有小程序角色的账号提示联系管理员，不默认授予家长身份。
- 多角色切换只变更工作台视图，不更换令牌、不申请模拟角色、不修改数据库授权。
- 已移除登录页开发模拟账号区域及首页“切换家长／教师”快捷入口；统一用已有账号手机号登录测试。首页顶部提供所有身份通用的“退出登录”按钮。
- 退出登录清除当前会话和权限；之后统一用手机号重新登录，不提供模拟角色切换入口。

## 验证码接口和部署

- GET /miniapp/auth/config：返回当前手机号登录是否可用、是否为测试验证码模式。
- POST /miniapp/auth/code：仅接受 phone，发起手机号挑战。
- POST /miniapp/auth/login：仅使用 phone、code，校验并消费验证码后登录／注册；角色不由客户端指定。
- 复用 Redis 保存短期验证码、错误次数和重发限制，无新增数据库表；匿名获取验证码不创建用户。
- 当前仅实现开发测试码，不发送真实短信。在 local/test 且 wechat.miniapp.phone-code-mode=development 时可用，页面明确显示测试码；prod/production 或未配置短信模式时拒绝获取和校验，不返回测试码。
- 旧免密开发身份入口也限制为 local/test，wechat.miniapp.mock-enabled 默认关闭，application-local.yml 显式启用。不要将 local profile 用于正式部署。
- 上线前需由短信服务完成真实发送对接，维持现有 phone/code 接口；当前没有接入真实短信供应商，生产短信登录保持关闭。

## 配置方式

在若依网页“系统管理→用户管理／角色管理”设置已有账号的角色和菜单权限。教务收款确认需要 system:tuition:confirm，并按职责分配 list、query、price、collect 等收费权限。优惠券管理入口只放在管理员工作台，发放仍由后端验证系统权限及管理员角色。

前端隐藏入口用于工作台分工；接口权限、家长数据归属与教师授课范围继续由后端现有鉴权负责。前端切分不会扩大服务器权限；网页新建任意编码的角色不会自动映射为这四类业务身份。

### 教务课次出勤审核（2026-10-19）

- 教师“学生出勤”中选择具体课次日期，完成每位学员点名后点击“提交点名表给教务”。记录直接进入教务／管理员首页“出勤审核”，不复制第二套学生点名数据。
- 教务默认查看待确认课次，可按日期筛选、切换已确认／全部。详情展示教师、上课时段、教室、提交账号和时间，以及点名人数、实到、正常到课、请假、录播、试听到课、调课到课；实到为正常＋试听＋调课到课。
- 一名教务或管理员点击“审核确认”即完成，取代旧双管理员确认。完成后锁定点名，保留审核人与时间；重复请求不覆盖原审核人、时间或图片。不增加短信、微信订阅通知或强制课堂图片要求。
- 主接口为 /miniapp/education/sign/list、/detail、/review；兼容旧 /miniapp/admin/sign 路径。服务端明确校验既有 education／admin 角色，不按校区限制；教师、家长不得访问审核接口，教师原有本人授课范围校验不变。
- 复用 edu_class_sign_in 的 schedule_id＋class_date 确定具体课次；enrollment_id／student_name、sign_status、source_type、remark 保存原点名。review_status=0 待确认、1 已确认，review1_admin_id/name/time 等原字段保存新单人审核事实。
- 旧版已完成记录不改写。旧版仅有第一次确认的记录不会自动通过，仍需点击确认归档；保留原 review1 信息，以原 review2 字段记下这次归档人和时间，不再要求两个不同账号。
- 服务端生成 submissionVersion，审核时在排课锁内重新校验。教师尚未被确认前重新提交点名会使旧版本失效，教务须刷新重看后确认；不同日期课次分别统计，不合并。
- 不新增数据库表、角色或字段，不执行全库导入或历史数据批量变更。需要重新打包／重启后端并重新编译小程序，协作者不要只更新小程序。
- 本地验证：244项小程序检查、6项独立临时MySQL库检查通过；后端打包和WXML编译通过。测试未确认现有开发库的真实课次，临时测试库运行后清理。

### 出勤审核异常与逐人更正（2026-10-19，追加升级）

本节是在上方首版单人确认功能上追加的修改；首版无需迁移，本次新增两列，必须先升级数据库再启动新版后端。

1. 教务或管理员进入“出勤审核→课次详情”。核对无误直接“审核确认”；发现错误填写原因，点击“审核不通过／标记异常”。
2. 异常课次显示原因，教师在“学生出勤”的课次详情可看到提示，不能覆盖原始点名；家长考勤显示待更正，不代表已确认。
3. 教务或管理员分别点击各学员“更正出勤”，从滚轮选择状态，在对应学员卡片填写原因；多人修改独立暂存，彼此不会覆盖。可以同时把甲设为请假、乙设为未到课，再点击“保存全部更正”。选择原状态会取消该学员的待保存修改。不按姓名匹配，不改报名、学员来源、教师原提交人／时间或原备注。
4. 待保存人数大于0时禁止“审核确认”，必须先保存全部更正。至少完成一次更正且没有待保存修改后，再点“审核确认”。课次重新统计并锁定，不提供已确认课次的随意解锁。相同账号可依次完成异常处理、更正和最终确认。

数据库仍使用 `edu_class_sign_in`，不新增学生、课程或出勤表：

| 字段 | 本次含义 |
| --- | --- |
| review_status | 原字段：0待确认、1已确认、2审核异常 |
| sign_status | 原字段：1到课、2录播、3请假、4试听到课、5调课到课；新增6未到课，不等同请假 |
| review_reason | 新增VARCHAR(500)，最近一次课次异常原因；不覆盖学员remark |
| review_history | 新增JSON，每行追加REJECT／CORRECT事件，记录旧状态、新状态、操作者ID／姓名、时间和必填原因；首次异常事件保留该行教师原提交状态 |
| review1_*／review2_* | 继续保留审核事实及旧版归档记录，不通过更正抹掉旧确认人 |

- 新增POST `/miniapp/education/sign/reject`、`/correct`，兼容`/miniapp/admin/sign`；仅现有education／admin角色可用。两者都校验课次、点名版本、原因；更正还校验signInId确实属于该课次，且新状态符合报名／试听／调课来源。
- `/correct`新增批量参数`corrections: [{signInId, signStatus, reason}]`，同批可包含不同状态及原因；兼容原单人`signInId/signStatus/reason`，但禁止混用。服务端先校验全部学员、重复ID、状态、原因和版本，再在同一事务中写入；任一条非法或中途SQL失败则整批不保存，每人分别追加历史。明确失败时页面保留全部待保存内容；结果未知则刷新核对，不自动重复写入。本次批量修复复用已有两列，无须再次迁移数据库。
- submissionVersion覆盖状态、异常原因与完整更正历史，避免改回原状态后旧页面仍能提交。异常、更正、最终确认和原教师提交共用排课锁；保存后刷新，不自动重试未知写入。
- 已完成一对一消课，或该教师当月已有已确认薪资结算单时，禁止直接标记／更正。异常点名不能继续确认消课。教师薪资汇总只使用review_status=1的出勤，待审核和异常行不计入；旧版半确认课次须先由教务归档。上述操作不自动扣／返课包，不更改收费、退款或结算金额。
- 协作部署：备份目标库、停后端，执行`database/migrations/20261019_sign_review_exception.sql`，再重新打包／启动后端并编译小程序。迁移可重复执行，不改写已有点名与审核记录；新库结构模板`database/schema.sql`已同步两列。不要把含业务数据的私有全量备份提交到GitHub。
- 验证：251项小程序检查、15项独立临时MySQL库检查通过，包含多人混合状态保存、独立原因、未保存阻止确认、明确失败保留草稿、重复／越界学员拒绝及第二人SQL失败整批回滚；同时保留已消课／结算拦截、旧单人兼容、教师覆盖拦截、迁移重复执行和薪资统计检查。后端打包和相关WXML编译通过。业务库不用于测试真实审核写入。

### 小程序退费处理补齐（2026-10-19）

- 教务、管理员首页增加“退费管理”，按 system:tuitionRefund:list 授权显示；收费详情也可跳转对应退费记录，不再要求必须转网页操作。
- 复用网页端 /system/tuition/refunds/list、/{id}、/{id}/review、/{id}/mark-refunded 接口，不新增数据库表或角色，不修改现有财务记录。
- WAIT_EDU：有 review 权限的教务或管理员填写核定金额，点击“确认金额并已阅”；驳回必须填写原因。
- WAIT_ADMIN：有 markRefunded 权限的管理员在线下实际退款后点击“已退款登记”；金额以教务核定记录为准，不能改金额、跳过初审或由家长确认到账。具备 review 权限的管理员也可驳回此阶段申请。
- 同一账号兼任时须依次完成两个步骤。单次请假、费用调整和退课沿用后端原有规则。历史流程保持只读并提示去网页核对，不自动改变旧申请。

- 本次仅修改小程序，无须数据库升级或重新打包后端；开发者工具重新编译后登录有相应授权的账号即可。
