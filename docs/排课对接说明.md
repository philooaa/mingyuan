# 课程与一对一对接说明

## 当前范围与入口

教师小程序统一从“我的课程”进入本人班课、一对一周课表、课程列表、报名处理和课次记录。教师只新增本人一对一课程，管理员保留班课管理。三端首页视觉延续原样，小程序管理员新增独立“交易管理”，若依也使用同名菜单。

新建改为“选择上课时段”页面：展示本人全部课程，在服务器确认可发布的固定时段内显示浅灰加号；点击后填写课名、年级和空闲教室。每次只发布指定日期的一节两小时课，不提供连续周数、自由时间或自由地址。旧系列课程及自由地点记录保留历史。

本版实现线下付款状态登记、学生课次账户、发放／收回、预约暂占、取消释放及教师课后消课。报价、金额计算、微信支付、真实退款、课后冲正及优惠券规则尚未接入；缺失金额不表示真实零元，也不创建空优惠券页面。

## 教师接口与资源校验

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | /miniapp/teacher/course/schedules | 本人班课、一对一及调课记录 |
| GET | /miniapp/teacher/course/availability?date=yyyy-MM-dd | 所选周固定时段与空闲教室 |
| GET | /miniapp/teacher/course/schedule/{id}/edit | 本人课程编辑资料 |
| POST / PUT | /miniapp/teacher/course/schedule | 发布一节一对一／修改本人课程 |
| DELETE | /miniapp/teacher/course/schedule/{id} | 删除完全没有业务引用的课程 |
| GET | /miniapp/teacher/course/profile | 后台学科及等级，只读 |
| GET | /miniapp/teacher/course/single/transactions | 本人报名及课次处理状态 |
| POST | /miniapp/teacher/course/single/{id}/decision | 确认、拒绝及取消处理 |
| POST | /miniapp/teacher/course/single/{id}/complete | 教师课后确认完成，课包正式消耗 |
| GET | /miniapp/teacher/course/single/{id}/history | 本人报名历史 |

创建只提交 courseClassName、gradeName、classroomId、startDate、timeSlot。教师ID、学科、结束时间、单节日期规则及编码由服务器确定。时间来自启用的 edu_time_slot 字典且必须两小时；客户端不能伪造其他起止时间。

发布即占用教师和教室，无人报名或停招仍占用；撤回没有有效报名的课程后才释放资源。取消／拒绝报名释放学员名额和课包暂占，不自动撤回课程。

ScheduleAvailabilityService 共用班课与一对一的真实日期、重复规则、调课记录及半开时间区间，首尾相接不冲突。发布、修改、调课及撤销调课在教师／教室资源锁保护下复核。教室已有未来课程不能停用，历史引用不能物理删除。

已有签到或按日期报名时，不直接改写教师、教室、时间、日期、学科及重复规则。无引用课程可从编辑页重新选择空闲时段与教室。历史缺日期课程按已确认的开发兼容方案保留待排，不要求先清理全部数据；不猜日期，不宣称空闲结果已满足实际运营准确性。

## 家长报名与课次规则

原报名页保留班课报名／一对一预约、学科、年级及多教师筛选。教师姓名优先绑定账号的 user_name，再回退昵称和历史姓名，按教师ID区分同名账号。旧多周课程折叠为课程卡片，展开选择具体日期。

家长列表使用 /miniapp/parent/single/lessons，提交沿用 /miniapp/parent/enroll，包含 scheduleId、classDate、studentName、contactPhone，增加：

| 字段 | 含义 |
| --- | --- |
| settlementMethod | C单次付费；P课包。旧客户端默认C |
| lessonAccountId | 选择已有孩子时必填；班课、一对一、单次付费和课包都绑定孩子，必须归属当前家长 |
| studentRequestKey | 新增孩子时必填的16至64位字母数字下划线／连字符请求键；重试保留，报名成功自动建零余额账户 |

单次付费不要求课包，由管理员登记线下付款；教师可以先确认未付款预约。课包要求可用额度充足，服务端按教师后台等级确定精英1次、资深2次，并保存等级与数量快照。等级缺配置时课包方式不可用，不猜倍率；单次付费仍可提交。

账户绑定明确孩子，不按同名、同手机号自动合并。同一家长多个孩子有不同账户ID；尚无报名的孩子也可建账户。课包跨学科使用，不设置期限，旧预约不随教师等级变更重算。

剩余包含暂占，可用=剩余−暂占。报名事务同时占用该日期唯一名额及额度；取消申请待处理保留暂占，拒绝报名或批准取消才释放。原开始上课后／已有上课历史的取消限制保留。

教师在课次结束且有对应报名、课程、日期匹配的有效到课签到后确认完成，正式减少剩余、增加消耗、追加流水；重复点击不重复扣次。完成后不能覆盖原签到，不因时间已过或管理员复核自动扣课。课后冲正等待团队后续接口。

家长通过 /miniapp/parent/lesson-accounts 及 /miniapp/parent/lesson-accounts/{id}/history 查看本人孩子余额和流水。原取消申请及报名历史接口保留。归属与权限由后端验证。

## 双端交易管理

若依 system/transaction/index 与小程序 pages/admin-transactions 共用 /system/eduTransaction，接口和服务均强制管理员角色。

| 方法 | 相对路径 | 用途 |
| --- | --- | --- |
| GET | /parents?keyword= | 查有效家长，覆盖首次报名学生 |
| GET / POST | /accounts | 兼容原账户查询／管理员新增孩子 |
| PUT / DELETE | /accounts/{id} | 修改孩子资料／删除未使用孩子 |
| GET | /personal-accounts?keyword=&pageNum=1 | 家长个人账户列表与全局待办数，每页30条 |
| GET | /personal-accounts/{parentId} | 家长信息、所有孩子与待办数量 |
| GET | /personal-accounts/{parentId}/records?kind=&pageNum=1&pendingOnly=false | enrollments课程付款／orders商城交易／history操作记录，各自分页 |
| GET | /pending-count | 有效未支付单次付费报名数量 |
| POST | /enrollments/{id}/child | 管理员核对旧记录关联孩子，提交accountId和reason |
| POST | /accounts/{id}/adjust | GRANT发放；WITHDRAW收回 |
| GET | /accounts/{id}/history | 原始课次流水 |
| GET | /payments?keyword=&pageNum=1 | 报名付款列表，每页30条 |
| POST | /payments/{id} | 登记付款／人工退款结果 |
| GET | /payments/{id}/history | 付款状态历史 |

建立账户、发放和收回提交稳定 requestKey，网络超时重试保留原标识。后端唯一键与账户行锁防重复记账。调整提交正整数 quantity 与 reason；收回不得超过可用额度，不能收回已消耗或仍暂占的课次，不删除账户或流水。

付款登记复用 edu_enrollment.pay_status，原报名编辑页也走同一服务。课包不登记单次现金付款，付款与报名确认独立，不自动转账或消课。仅已支付记录可登记人工退款结果，已退款历史不能直接覆盖回付款状态。

## 数据库与迁移顺序

| 表 | 用途／本版变化 |
| --- | --- |
| edu_teacher_profile | 既有业务扩展，教师学科与等级 |
| edu_course_schedule | 复用课程；网格唯一键仅约束班课，一对一按真实日期占用 |
| edu_enrollment | 追加结算方式、账户ID、等级／扣次快照和完成信息 |
| edu_enrollment_event | 既有报名历史，追加完成与付款登记事件 |
| edu_student_lesson_account | 新增明确学生账户及课次余额 |
| edu_lesson_credit_event | 新增只追加的发放、收回、暂占、释放及消耗流水 |

业务外键使用 InnoDB有符号BIGINT，引用已有用户、账户或报名主键，ON DELETE RESTRICT / ON UPDATE RESTRICT。不修改 sys_* 表结构，只添加正常若依菜单与管理员菜单授权数据；不导入学生、课包余额或付款数据。

接收者先停止对应后端、备份自己的数据库，核对迁移状态，不能整库覆盖：

1. 使用团队MySQL8.0基线；团队财务字段尚缺时按其说明核对 database/migrations/20261007_finance_dashboard.sql。
2. 执行 RuoYi-Vue-master/sql/20261011_teacher_profile_incremental.sql，兼容标准若依及已有旧教师字段的环境。重复执行不覆盖新表配置，不删除旧列。
3. 未完成旧一对一结构时才执行 RuoYi-Vue-master/sql/20261009_one_to_one_incremental.sql。已存在字段时先核对，不直接重跑。
4. 执行 RuoYi-Vue-master/sql/20261011_one_to_one_fixed_slots_credits.sql；其中ALTER只执行一次。部分失败先检查结构，不直接重跑。已经完成2、3的环境只执行第4步。
5. 比较原表行数、系统表结构及用户数据，检查新列、外键、班课网格唯一键和原一对一日期名额唯一键。旧报名默认单次付费，不补造余额或历史扣次。

在仓库根目录，使用接收方自己的账户和数据库名：

```bash
mysql --default-character-set=utf8mb4 -u root -p mingyuaneduminiapp --execute="source RuoYi-Vue-master/sql/20261011_one_to_one_fixed_slots_credits.sql"
```

教师学科／等级沿用若依“用户管理→教师授课配置”。原用户更新导入模板新增可选“教师授课学科”“教师等级”列，等级接受elite／精英教师、senior／资深教师；空列保留原配置。先建教师账号并分配教师角色，再更新导入业务资料，导入不自动提升角色。资料失败时该行用户更新回滚，旧模板仍可用。

## 个人账户与孩子信息（2026-10-11）

- 双端管理员“交易管理”先显示家长个人账户，再进入孩子课包、课程付款、商城交易与操作记录；原课次发放、收回和付款登记服务共用。家长首页新增“我的账户”；点击右上角孩子标签进入“孩子信息”，可新增、修改、删除未使用孩子。三端首页风格保留。
- 孩子身份复用 edu_student_lesson_account.account_id，无需新建表或增加列。新增只有零余额，家长不能自己发放、收回或标记付款。资料修改只改姓名、年级、联系电话，不改家长、余额、原报名姓名和原扣次快照。有余额、已消耗、报名或额度流水的孩子不能删除。
- 家长 API：GET /miniapp/parent/account 返回本人信息、孩子、待办和未关联数量；GET /miniapp/parent/account/records 接收kind=enrollments/orders/history、pageNum及pendingOnly；GET /miniapp/parent/account/pending-count。POST /miniapp/parent/children 新增，PUT /miniapp/parent/children/{id} 修改，DELETE同地址删除未使用孩子；孩子列表继续GET /miniapp/parent/lesson-accounts。后端由当前token确定家长，不接受客户端指定归属。
- 家长报名下拉选择已有孩子，或新增孩子并提交姓名、联系方式与稳定请求键。服务端在同一报名事务内校验／建立账户并绑定lesson_account_id，失败一起回滚；课包报名只能选择余额足够的既有孩子。现金绑定账户不暂占、不扣次。若依代报名也选择或新增孩子，并复用名额与初始考勤写入。班课查重优先稳定孩子ID，改名不能绕过原报名。
- 旧记录按parent_id汇总，不按姓名自动创建或合并孩子。未关联旧报名始终可见，管理员核对后选择本家长孩子并填写说明，追加LINK_CHILD事件；已有关联不能任意改写。异常课包历史须先核对原暂占流水，不能用现金旧记录关联功能改写余额归属。
- 待办只统计del_flag=0、status=0、待确认／已确认／报名成功、C结算且未支付的报名，一条报名计一次；取消、拒绝、课包、已支付／退款不计入。商城交易可查看，未付款商城订单不加入课程待办。管理员交易入口、家长我的账户入口、家长账户行与课程付款标签显示数字角标，0隐藏、超过99显示99+；按当前身份刷新，迟到响应不污染另一角色。
- 课程付款、商城订单按COALESCE(update_time,create_time)倒序、稳定来源ID排序；操作历史按原事件时间倒序分页。查看不改业务时间。额度流水独立显示“次”，课程金额未接入时明确未提供；商城仅展示原应付、可信实付及退款金额，不将课包扣次重复记为现金收入。价格、真实支付退款与优惠券保持暂缓。
- 本次复用现有59表，无数据库结构迁移、业务数据导入或旧记录自动回填。需要先具备本文件前述课次与教师资料增量结构。
- 验证包含37项小程序交互回归、36页面及共享WXML/WXS、两处若依模板样式与完整生产构建；隔离MySQL覆盖孩子增删改、归属保护、零余额自动关联、同名分离、改名查重、失败回滚、并发幂等、付款计数、人工旧记录关联与历史排序。测试只使用明确临时库并清理，业务库不写测试记录。
