# 学生出勤（总览、统计与复核）

## 入口与职责

2026-10-20合并口径：教师提交点名表，教务或管理员一人复核即可完成，不再要求第二名教师／管理员确认。异常由教务或管理员核实、更正，教师不能覆盖异常课次。以下流程以此新口径为准；后面的早期验证记录仅为历史记录。

管理员及教务首页“学生出勤”独立于教师“打卡复核”，进入后可查看出勤总览和复核。待复核、审核异常按课次分别展示，以排课编号及日期去重；异常仍属于教务处理事项。回到首页和定时刷新会更新，切换账号或角色后丢弃迟到响应。

家长可立即查看当前孩子的出勤结果，详情中次要显示“教师已登记／教务核实中／已核对”。不要求家长确认，不增加家长待办。家长查询仍按当前孩子的稳定账户及报名编号校验归属，不能查看其他孩子或班级的复核历史。

## 流程和页面

| 状态 | 教务／管理员操作 | 教师操作 |
| --- | --- | --- |
| 待复核（0） | 核对名单、出勤人数和结果；单人确认或填写原因标记异常 | 在尚未进入审核前可修改重提，旧页面不能覆盖新版本 |
| 审核异常（2） | 核实并批量更正学员出勤，逐人填写原因，再重新确认 | 查看原因，不可修改或重新提交覆盖 |
| 已复核（1） | 查看原记录及操作历史 | 锁定，不能覆盖原签到 |

复核列表按待复核、审核异常、已复核查看。详情支持“审核异常／审核通过”；异常后在小程序由教务或管理员勾选多名学员、修改结果并提交，再确认复核。若依网页确认／标记异常与小程序共用服务；网页标记异常后提示到小程序核实更正，不退回教师。课堂图片选填，已复核课次锁定，重复确认不覆盖原审核事实。

## 出勤总览与学生统计

- 选择课程及日期范围，按“学生 × 实际已登记日期”展示总表。课程可按课程名称、教师、年级或学科搜索，本课学生可按姓名或家长手机号筛选。
- 日期列较多时左右滑动，学生栏固定；日期标题和出勤内容使用同一滚动区域。左右行高统一，姓名、家长尾号及到课／请假统计分别显示，姓名不会被纵向压缩裁切。
- 点击学生查看统计，点击已登记单元格查看对应课次明细。仅可靠关联到稳定学生ID的记录支持跨课程统计，历史未关联报名及临时记录不按姓名猜测合并。
- 到课合计包含普通、试听和调课到课；请假、录播分别统计。未记录显示“—”，不当作缺勤，不据此扣次或结算。同一学生同课次出现多条记录时显示“待核对”，不计入确定的出勤结果。
- 当前姓名与原签到姓名快照分别保留。统计包含待复核记录，并单独显示复核状态；查询为只读，不修改考勤、请假或财务数据。
- 明细每页30个课次；总览超过5000条原始记录、120个日期或8000个格子时明确提示缩小日期范围，不静默截断。

总览复用原签到服务、报名及学生身份关系，没有新增统计表。只读接口为 `/miniapp/admin/sign/courses`、`/overview`、`/student-summary`，同时兼容 `/miniapp/education/sign` 前缀，后端校验教务／管理员权限及学生与课程的关联；未到课状态6单独统计，不把没有签到记录的日期当成未到课。

已复核记录本轮不开放普通编辑或退回；涉及已结算记录的事后更正须单独核对引用，不自动重算退款、课次或工资。

## 复用与数据保护

复用 `edu_class_sign_in`，只补三个字段，不新增表，不修改 `sys` 结构：

- `review_reason`：课次异常原因，最多500字。
- `review_version`：递增课次修改版本，阻止陈旧页面覆盖教师提交或另一审核人处理结果；小程序同时兼容点名表内容哈希 `submissionVersion`。
- `review_history`：逐行保留提交、异常、更正及确认的操作者、时间、原因与快照，不用某一学员的历史覆盖其他学员。

报名学员按报名ID区分，同名孩子不能合并；无报名编号的试听/调课学员沿用原身份规则。更正复用原签到ID，移出名单的行标为无效，保留历史；不再删除后重建。原备注继续用于学员说明和联系方式。

先备份，再核对执行 `database/migrations/20261015_attendance_review.sql` 与 `20261019_sign_review_exception.sql`；两份均可重复检查执行，只扩展结构，不改原签到、复核状态或旧两位管理员信息。本地如果只安装过异常更正迁移，仍需补20261015中的 `review_version` 字段。旧双人已完成记录继续锁定；原只确认一人的历史课次保留原信息，由教务／管理员显式归档，不自动改写。

原接口地址与列表、明细和签到字段保留。网页确认体带 `action`（APPROVE确认、RETURN兼容标记异常）、`reason`、`reviewVersion`；小程序继续使用 `/reject`、`/correct` 和 `submissionVersion` 哈希。审核必须带有效版本，教师提交使用 `reviewVersion`；未带教师提交版本仅允许原始0版本。两端操作同一记录和锁，旧页面不能绕过状态保护。确认重试幂等，不追加第二次确认或覆盖历史图片。

班课请假继续按原申请、授课教师审批及已复核保护工作。按课次退款继续要求已复核的请假考勤；工资核算沿用原到课统计。本次确认不直接触发退款、发薪或课包消耗，一对一仍由原教师完成服务处理。
